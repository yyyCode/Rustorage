# 已知局限

这份清单存在的理由：上面那些数字里，**有几个看起来比实际能支撑的结论更强**。
逐条列清楚，免得以后被人当成功劳引用。

## 测量本身的局限

### 计数与墙钟来自同一次运行

`IoLog` 的每个热路径调用都做一次原子自增（`benches/io_modes.rs:112-128`），
所以它必然影响时序。要拿墙钟当结论时，得另做一个不带计数的版本。
本次没有这么做——**墙钟一律只当佐证用**。

### `read_bytes` 不是确定性的

它**不参与** `measure` 的逐轮相等断言，原因与 Task 6 记的是同一件事：

`meta.xl` 里的 `version_id` / `data_dir` 两个 UUID 走 `HeaderWire` 的 `[u8; 16]`
桥接字段编码，而 `rmp_serde` 对每个 ≥ 0x80 的字节要多花一个 `uint8` 前缀、其余用
1 字节正整数。于是**同一个字段的编码长度在 19~35 字节之间随随机字节浮动**，
两次 PUT 一份相同的内容会产出**不同长度**的 `meta.xl`。

这是既有的格式性质，与本次改动无关，但它会让「读不同对象的元数据」这类负载的
字节数逐轮差几百。**调用次数（reads/stats/lists）才是确定性的那部分。**

### 量的是稳态，不是冷启动

每次负载前跑一轮热身并丢掉（`benches/io_modes.rs:211`）。所以 L2 主测里那个
**0 次 IO** 是「**缓存已热**」这个条件下的数，**不是**「第一次请求」的数。
第一次请求仍然要比旧模式多做一轮 `list_dir` + `read_meta`。

### 规模是被「跑得完」倒推的

种数据要写 `(REPEAT + 1) × L2_DISTINCT + L3_KEYS + 2` 个对象 × 2 个 set，
每次 PUT 都要在 6 块盘上 fsync——实测约 **33 ms/次**。原计划的 256 MiB / 10k key
光种数据就要十几分钟，所以降到了现在的 64 MiB / 600 key。

**L3 的倍数受此影响最大**：桶只有 600 条而一页要 100 条，早停收益的上限本来就只有
5/6。桶越大，`bounded_listing` 在分页负载上的相对收益越明显。

## 没测到的东西

| 项 | 为什么没测 |
|---|---|
| **fsync / 组提交** | `crates/disk/src/fsx.rs::sync_dir` 在 **Windows 上是 no-op**，这条线是平的假线（DESIGN §1.2）。要测得上 Linux。 |
| **内存上界（RSS）** | `unsafe_code = "forbid"` 排除了全局分配器探针。`allocs` 数的是「显式扩了几次缓冲」，**不是字节数**，也推不出 RSS 的变化。 |
| **并发** | 所有工作负载都是单线程串行的。多请求并发下的表现（尤其是 `metadata_cache` 的锁竞争）没测。 |
| **真实 `max-keys` 分布** | L3 的两个数字是**端点**（凑一页 vs 全扫），中间的分布没测。 |
| **网络/协议层开销** | 基准直接调 `ErasureSet`，不过 HTTP、不过 `s3s`，所以量到的全是存储层。 |

## 结论的适用边界

### L3 是唯一有负数的负载

`bounded_listing` 在「必须扫全」时 `list_dir` 多 33%、慢 13%。这是有序遍历每层前瞻
的**真实代价**（设计规格 §4.3 预告过），不是缺陷。**这个机制不是无条件的提速。**

### L3 有一个已知的残留假设

有序遍历假定 **key 的字节序与目录层级顺序一致**。对 `p/a` 与 `p-x` 这类组合
（`-` = 0x2d 小于 `/` = 0x2f）该假设不成立，分页可能提前收尾。彻底的修法是引入
命名空间索引（DESIGN §20 Phase 2）。

**`old` 模式不受影响**（它靠 BTreeSet 全量排序），本次对比的两条路径也都正常——
但把 `bounded_listing` 当默认行为之前，**这一条必须先解决**。

### L4 的墙钟差异不是结论

主测两行的墙钟差（1619 vs 1916 ms）在噪声量级上，**不能读成「新模式更慢」或
「更快」**。这个机制省的是分配，而这次负载的瓶颈在别处。

### 对照位的性质

阴性对照位的「差异接近 0」证明的是**这次测量没有在量别的东西**，不是「新机制没用」。
唯一的例外是 L3 列全桶的 `lists`——那里的差异是设计的一部分。
