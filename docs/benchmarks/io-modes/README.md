# 读写路径 IO 模式基准

这套基准量的是 **`IoModes` 四个机制逐个打开之后，读/写路径的 IO 工作量怎么变**。
新旧两条路径在同一份代码里共存，基准把两个模式跑在**同一批工作负载**上，逐项对比。

| 机制（`IoModes` 字段） | 动的是哪条路径 | 主测工作负载 |
|---|---|---|
| `ranged_shard_read` | 范围读只读命中的块 | L1 |
| `metadata_cache` | 缓存版本解析结果 | L2 |
| `bounded_listing` | 有序增量遍历 + 分批列举 | L3 |
| `pooled_write_buffers` | 单次 PUT 内复用分片缓冲 | L4 |

`old` = 四个全关（`IoModes::default()`），也就是改动前的行为；
`new` = 四个全开（`IoModes::ALL`）。

## 结论摘要

一句话：**三个机制有明确收益，一个有明确代价，都可能只在特定负载形态下成立。**

| 负载 | `reads` | `read_bytes` | `stats` | `lists` | 墙钟 |
|---|---|---|---|---|---|
| L1 范围读（64 MiB 对象取 100 字节） | 12 → 6 | **100 676 742 → 1 573 056** | 12 → 6 | 6 → 0 | 754 ms → 15 ms |
| L2 同 key 2000 次 HEAD | **12 000 → 0** | 2 256 000 → 0 | 12 000 → 0 | 12 000 → 0 | 8 341 ms → 4 ms |
| L3 从 600 key 凑一页 100 条 | 600 → 600 | ≈ 不变 | 2 404 → 1 603 | **11 430 → 7 230** | 3 396 ms → 2 195 ms |
| L3 列全桶 | 5 412 → 5 412 | ≈ 不变 | 7 216 → 7 216 | **16 242 → 21 654**（**倒退 33%**） | 7 486 ms → **8 488 ms（慢 13%）** |
| L4 4 次 16 MiB PUT | 0 → 0 | 0 → 0 | 0 → 0 | 24 → 24 | 1619 ms → 1916 ms（噪声量级） |

L4 的证据不在 IO 列（这个机制**不动 IO**），而在分片缓冲的显式增长次数：**256 → 16**。

**唯一的负数是 L3 列全桶。** 有序遍历每层多一次前瞻 `list_dir`，把「必须扫全」的
负载略微拖慢，换「只要一页」的负载早停。这是设计规格 §4.3 预告过的代价，
不是缺陷，但也不能不提。

## 怎么读这套数字

**计数是主证据，墙钟是佐证。** 「旧模式每块盘读 100 MB，新模式读 1.5 MB」是构造性的
事实，换台机器仍然成立；「快了 49 倍」会随机器、缓存、后台进程漂移。本文里的倍数
只在**这次运行**的语境下成立。

**每个主测都配了阴性对照。** 对照位不证明新机制有多快，它证明这次测量没有在量别的
东西——对照位若显著非零，先修测量再谈结论。唯一的例外是 L3 列全桶的 `lists`。

**计数逐轮相等是被断言过的，不是看出来的。** `measure`（`benches/io_modes.rs:206`）
在每轮结束后比较 `reads`/`stats`/`lists`/`allocs`，不同就直接 panic。`raw/` 下两次
完整运行也验证了跨运行的稳定性：**计数列逐项相同，`read_bytes` 与墙钟每次都不同**
（对照表见 [results.md](results.md#跨运行的一致性)）。这不是缺点——它恰好说明
哪些数字可以当证据、哪些只能当参考。
