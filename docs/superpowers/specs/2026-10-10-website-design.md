# Rustorage 官网（静态展示站）设计

> **目标**：一个可以挂到域名上、公网访问的**产品官网**。展示项目亮点与设计，
> **不讲底层代码、不讲怎么启动**。形制对标主流互联网产品官网。

**日期**：2026-10-10
**状态**：设计已确认，进入实施

---

## 1. 定位与非目标

**是**：一个单页长滚动的静态站。读者是「第一次听说这个项目的人」——可能是开源社区的
路人、技术选型的评估者，或者只是点进来看看的人。它要在 30 秒内回答三个问题：
**这是什么**、**凭什么值得看**、**边界在哪**。

**不是**：

| 不做 | 理由 |
|---|---|
| 文档站 | `docs/DESIGN.md` 已经在仓库里，官网只负责把人**指过去** |
| 博客 / 更新日志 | 没有持续产出内容的人，不要开这个坑 |
| 任何写操作、登录、表单 | 静态站，没有后端 |
| 暗色主题切换 | 只做一套亮色。多一套主题就多一套要同步维护的颜色 |
| 搜索 | 单页，浏览器自带的 `Ctrl-F` 够用 |
| 第三方脚本 / 字体 / 图片 / 分析 | 见 §3 |

---

## 2. 硬约束

| 约束 | 含义 |
|---|---|
| **零构建** | 没有 npm、没有 node_modules、没有构建产物。源码就是产物，改完刷新即见 |
| **零外部请求** | 不发任何指向第三方的请求：无 CDN、无外部字体、无外链图片、无分析脚本。字体走系统栈 |
| **`file://` 可用** | 双击 `index.html` 也要能看。这意味着**不能用 ES module**（`file://` 下会被 CORS 拦掉），一律用经典 `<script>` |
| **无内联样式/脚本** | 样式全部走 `style.css` 的类名，脚本全部走外链。这样在任何严格 CSP 下都能跑，也与控制台的既有做法一致 |
| **零位图** | 所有图形用内联 SVG 或 CSS 画。没有 `.png` / `.jpg`，因此永远清晰、无版权问题、仓库里也没有二进制资产 |

## 3. 技术形态

新建顶层 **`website/`**，与 `docs/` `crates/` 平级。**不进 Cargo workspace**，
不参与 `cargo` 的任何命令，不碰 `.github/workflows/`。

```
website/
├── index.html          单页，全部内容与语义结构
├── assets/
│   ├── style.css       亮色主题、排版刻度、组件
│   ├── i18n.js         中/英两份文案树（唯一需要改文案的地方）
│   ├── app.js          语言切换、导航折叠、滚动进场、数字滚动
│   └── logo.svg        wordmark 标记
├── favicon.svg
├── robots.txt
├── 404.html
├── check.sh            本地自检（护栏，不是流水线）
└── README.md           本地预览、部署、改文案指南
```

**为什么不放进 `docs/`**：`docs/` 是设计文档（人读的 Markdown），`website/` 是一个
**部署产物**（要上传给托管方的目录）。两者生命周期不同，混在一起会让「哪些文件要发布」
变得含糊。

## 4. 视觉方向：亮色文档风

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#ffffff` | 页面底 |
| `--bg-soft` | `#f8f9fb` | 交替区块底、代码块 |
| `--text` | `#1a1a1a` | 正文 |
| `--text-dim` | `#5c6370` | 次级文字 |
| `--line` | `#e6e8ec` | 分割线、卡片边框 |
| `--accent` | `#2563eb` | 主色：链接、CTA、强调 |
| `--accent-soft` | `#eff4ff` | 主色的浅底（标签、高亮块） |
| `--ok` | `#15803d` | 「可读写」这类肯定态 |
| `--warn` | `#b45309` | 「已知代价」这类提示态 |

- **字体**：系统栈，不引外部字体。字号成刻度（`13/15/17/22/32/48`），不散落魔法数字。
- **分隔**：区块之间用细分割线 + 大面积留白，不用卡片堆砌。这是「文档站风」与
  「SaaS 落地页」的区别所在。
- **响应式**：`≤720px` 折叠导航、单列；`≤480px` 缩小首屏字号。
- **动效**：只有两处——区块进场淡入上浮、首屏数字从 0 滚到目标。
  两者都在 `prefers-reduced-motion: reduce` 下一并关闭。

顶部 **sticky 导航**（左 wordmark、中锚点、右语言切换），八个区块：

| # | 区块 | 锚点 | 内容 |
|---|---|---|---|

| 2 | 它是什么 | `#what` | 一段话 + 六宫格能力卡 |
| 3 | 三个设计亮点 | `#design` | 三张深度卡 |
| 4 | 设计图解 | `#diagrams` | 四张 SVG/CSS 图 |
| 5 | 性能数据 | `#bench` | 引用 `docs/benchmarks/` 的真实数字 |
| 6 | 刻意不做的事 | `#scope` | 已知限制翻成卖点 |
| 7 | 路线图 | `#roadmap` | 四个方向的纯文本时间线 |
| 8 | 页脚 | — | MIT、仓库、文档链接 |

### 5.1 首屏

- 名字 **Rustorage**，一句话定位，副标题一行；
- **三个数字卡**（这是全站的信息密度锚点）：

  | 数字 | 中文 | 英文 |
  |---|---|---|
  | `64×` | 范围读少读的字节 | Fewer bytes read on a ranged GET |
  | `0` | 元数据解析的磁盘调用（缓存命中时） | Disk calls to resolve metadata (cache hit) |
  | `4+2` | 六盘配置，掉两块盘仍可读写 | Six disks; survives two failures |

- 两个 CTA：`看设计` → `#design`、`看性能数据` → `#bench`。

### 5.2 它是什么

一段话讲清「从零实现、S3 兼容、纠删码而非多副本、单个可执行文件、元数据与数据同盘」，
然后六宫格：

1. **纠删码**——Reed–Solomon，`N` 块盘 = `data + parity`，`2 ≤ N ≤ 16`；
2. **单节点多盘**——所有盘构成一个 erasure set，掉盘不破 quorum 就照常读写；
3. **S3 数据面**——桶与对象的增删查列、范围读、条件请求、虚拟主机寻址、SigV4；
4. **完整性**——每份分片带 keyed BLAKE3 校验和；
5. **崩溃一致性**——`.staging-*` 写入 + rename 提交 + fsync；
6. **运维面**——`/health`、`/ready`、`/metrics`，外加一个零构建的只读控制面板
   （桶列表、目录式对象浏览、对象详情与下载、服务状态与指标；签名在浏览器里现算，
   凭据不落盘）。

### 5.3 三个设计亮点

**① 纠删码，而不是多副本**
同样 6 块盘：三副本只能存 2 块盘的数据，`4+2` 能存 4 块盘——空间效率翻倍。
容错量化：掉 2 块仍可读写；再掉 1 块（剩 3 < 读 quorum 4）→ **读失败返回 503，
而不是返回坏数据**。这三个 quorum 公式是全站的「设计可信度」锚点。

**② 绝不返回坏数据**
每份分片带 keyed BLAKE3 校验和，静默位翻转会被检出（`BitrotMismatch`）。
**并如实写出代价**：范围读只校验它真正读到的块，所以「完整 GET 能发现块 7 的损坏，
只读块 1 的范围 GET 不能」是预期行为——换来的是可用性上的单向收益（一块盘只在**实际
需要的那几个块**损坏时才被判为缺块）。

**③ 崩溃后看不到半成品**
写入 `.staging-*`，rename 提交，fsync 文件与父目录。崩溃之后要么看不到这个对象，
要么看到的是一个完整对象——不存在中间态。

### 5.4 设计图解（四张图，全部 SVG/CSS 手绘）

1. **三级寻址**：`bucket` → `key` → 版本目录（UUID）→ `meta.xl` + `part.N`；
2. **写路径**：请求体 → 分块 → 编码成 `data + parity` 分片 → 写 staging →
   fsync → rename 提交。逐块流式，峰值内存是一块而不是整份；
3. **掉盘矩阵**：6 盘 `4+2`，掉 0/1/2 块 → 可读可写；掉 3 块及以上 → `503`。
   用一排盘位方框表示，掉的那几块变灰打叉；
4. **范围读对比条**：同一份 64 MiB 对象上取 100 字节，旧路径读 100.7 MB、
   新路径读 1.57 MB，两根横条按真实比例。

### 5.5 性能数据

数字**全部来自 `docs/benchmarks/io-modes/`**，不新造：

| 项 | 数字 |
|---|---|
| 范围读少读的字节 | 100 676 742 → 1 573 056（64×） |
| 同 key 重复 HEAD 的磁盘调用 | 12 000 → 0 |
| 分页列举的目录遍历 | −37%，墙钟快 1.55 倍 |
| 单次 PUT 内复用分片缓冲 | 显式扩容 256 次 → 16 次 |

**并且把负面数字一起放上去**：
「当请求必须扫完整个桶时，新的有序遍历反而多 33% 的目录遍历、慢 13%——这是每层
前瞻的代价，设计时就预告过。」

同时写明读法：**计数是主证据（可复现），墙钟是佐证（随机器漂移）**；两次完整运行的
原始输出在仓库里可查。这一条不给结论、只给方法，读者自己去核对。

### 5.6 刻意不做的事

把 `README §7` 的已知限制翻成正面表述——**有边界的 MVP 比没边界的半成品可信**：

- 不支持 multipart（因此单次 PUT 上限约 8 MiB）——刻意，不是遗漏；
- 单节点，无多节点、无自动自愈；
- 只监听 `127.0.0.1`，无 TLS，HTTP/1.1；
- 没有组、没有外部身份源（OIDC/LDAP）、没有管理 API；
- 列举走全盘遍历，没有索引。

### 5.7 路线图

多节点与池化 → multipart 流式上传 → TLS → 自动自愈 → 命名空间索引。
纯文本时间线，**不写日期**（没有承诺就没有食言）。

## 6. 双语方案

`index.html` 里所有文案节点带 `data-i18n="<key>"`，两份文案树在 `assets/i18n.js`：

```js
window.RUSTORAGE_I18N = {
  zh: { "hero.tagline": "从零实现的 S3 兼容对象存储", ... },
  en: { "hero.tagline": "An S3-compatible object store, built from scratch", ... },
};
```

`app.js` 负责：

1. 首次访问按 `navigator.language` 猜（`zh*` → 中文，否则英文）；
2. 用户切换后记进 `localStorage`，下次优先用；
3. 应用时改 `document.documentElement.lang` 与 `<title>`；
4. 缺失的 key **不静默**：`console.warn` 列出键名，并由 `check.sh` 在提交前拦住。

**为什么不做两份 HTML**：结构会重复，改一次版式要改两处，早晚不一致。

## 7. 无障碍与元信息

- 语义标签：`header` / `nav` / `main` / `section[aria-labelledby]` / `footer`；
- 语言切换是真正的 `<button>`，带 `aria-pressed`；导航折叠带 `aria-expanded`；
- 焦点可见（`:focus-visible` 描边）；跳过导航链接（`跳到主内容`）；
- `prefers-reduced-motion: reduce` 关掉进场与数字滚动；
- `meta description`、Open Graph（`og:title` / `og:description` / `og:type`）、
  `favicon.svg`、`robots.txt`；
- **不做** `hreflang`：单 URL 双语切换，`hreflang` 在这里不适用，写了是错的。

## 8. 本地自检 `check.sh`

不是流水线，是一个可以随时手跑的护栏。四条：

1. **没有外部请求**：`index.html` / `*.css` / `*.js` 里不允许出现 `http://` 或
   `https://` 的 `src=` / `href=`（指向仓库与文档的**页面链接**允许，用白名单）；
2. **没有内联样式**：`index.html` 里不出现 `style=`，JS 里不出现 `.style.` 写入；
3. **双语键对齐**：`i18n.js` 里 `zh` 与 `en` 的键集合完全相同；
4. **HTML 里用到的 `data-i18n` 键，两棵树里都有**（反向也查：树里有、HTML 里没用的
   键报出来，避免死文案）。

跑法：`bash website/check.sh`，输出 `WEBSITE: OK` 或逐条列出问题。

## 10. 部署（写给用户，不在本次实现范围）

站点是纯静态目录，**整个 `website/` 目录原样上传即可**。三种常见做法：

- **GitHub Pages**：仓库 Settings → Pages → Source 选分支与 `/website` 目录；
  自定义域名在同一页填 Custom domain（需要在域名侧加 CNAME 记录）；
- **Cloudflare Pages / Netlify / Vercel**：直接把 `website/` 作为发布目录；
- **自己的 Nginx**：`root /path/to/website;`，注意配 `404.html` 为错误页。

**本次不加任何 CI/workflow**（用户明确要求）。上面这些写进 `website/README.md`。
